# 数据库结构精简记录

2026-10-14 已在本机 `zhitu_classroom` 执行。本轮从 22 张基础表、30 个物理外键调整为 **17 张基础表、1 个原有视图、0 个物理外键**。并非所有企业都弃用外键；这里采用的是本项目明确选择的应用层关联校验方案。

| 原设计 | 本轮结果 |
| --- | --- |
| 所有 FOREIGN KEY 约束 | 删除约束，保留关联字段、主键、唯一约束和普通查询索引 |
| coins | 删除表，取消投币 API 及推荐中的投币信号 |
| comment_moderation | 将 hidden 迁入 comments.hidden，然后删除原表；保留讨论隐藏和恢复 |
| admin_audit | 备份后删除表，移除审计 API 和管理菜单；不再保存管理操作流水 |
| account_status | 将 disabled 迁入 users.disabled，然后删除原表 |
| sessions | 迁入 users.session_token_hash、users.session_expires，然后删除原表 |

用户表保持实际名称 `users`，没有重命名为 `user`。会话摘要使用 SHA-256，带唯一索引，未登录时摘要和过期时间均为 NULL。Cookie 中的随机令牌仍使用 HttpOnly、SameSite；密码仍使用原有 scrypt 摘要。

用户已选择每个账号只保留一次登录。迁移为每个正常账号保留未过期且过期时间最晚的一次会话，其余失效；同一过期时间用令牌排序确定唯一一条。停用账号不保留会话。新登录替换此前登录；旧会话调用退出接口不会清掉新会话。管理端停用账号会清除会话，重新启用不会恢复旧会话。

## 运行方式

已经迁移完成的本机数据库不需要再次操作。其他旧版 22 表库使用相同版本的代码执行：

```powershell
node scripts/simplify-schema.mjs
# 停止该网站及所有其他业务写入后执行：
node scripts/simplify-schema.mjs --apply --maintenance
npm run db:check
npm start
```

预检只读取元数据、数量和逻辑关联，不输出用户记录。应用阶段先备份，生成 `before.json`、`apply.sql`、`rollback.sql` 后再修改。MySQL DDL 会隐式提交，失败不等于事务自动回滚。`rollback.sql` 适用于完整迁移后、网站仍停机且尚无新写入时恢复；若执行到中途失败，应结合 `failure.json` 的执行条数和实际结构逐项恢复，不能盲目执行完整恢复脚本。

本次业务备份目录：`database/backups/simplify-2026-10-14T10-46-08-576Z/`。备份包含旧密码摘要和会话信息，仅保存在私有目录，已被 Git 忽略，不可作为论文附件、静态下载或公开仓库内容。完整原始结构在备份中；保留表记录数迁移前后逐表核对一致。原 5 个用户、42 条课程记录（其中 33 门上架）、2221 条章节记录、笔记、收藏及学习记录均保留。

## 无外键后的维护责任

- 主键和唯一索引仍拒绝重复数据；名为 `fk_…` 的普通索引不再是外键约束。
- 接口按服务端会话判断用户，检查课程、章节存在性与章节归属；笔记仍有私有归属校验。
- 管理端继续使用权限、事务与行版本检查，仅下架课程或停用账号，不提供用户/课程/章节硬删除。
- 手工 SQL 可以插入无效关联或删除被引用对象，数据库不会再自动拒绝、级联删除或置空。维护人员需要自行处理关联；`relationships.mjs` 记录逻辑关系，迁移预检会检查孤儿引用。
- 原管理审计功能已经取消，不把权限校验或普通服务日志描述为操作审计。
- 推荐模型版本升为 3；旧模型失效并回退到内容/热门排序。新训练只读取收藏和最近访问，仍需通过离线门控。
- 原 SQLite 数据、旧 ER 图和旧补丁属于历史资料，不能据此覆盖当前 MySQL。旧 SQLite 初始化被明确阻止，不会自动丢弃旧会话数据。
