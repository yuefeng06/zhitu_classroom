# 代码格式说明

本次规范只整理排版，并建立后续可重复运行的格式检查。不引入前端框架，不修改数据库记录。

## 规则

- JavaScript：两空格缩进、分号、优先单引号、箭头函数参数带括号、允许尾逗号；长函数、对象和调用展开，目标行宽 100 字符。
- CSS：两空格缩进，选择器与属性按格式器展开；保留样式顺序，不合并重复规则，不修改主题色。
- HTML：统一缩进和属性排版，根据元素的默认显示类型保留行内空白，并通过页面回归检查布局。
- JSON：两空格缩进；只格式化明确列入范围的项目配置。
- SQL：两空格缩进和查询分段，保留关键字现有大小写；不执行语句。
- PowerShell：四空格缩进、统一操作符空格和大括号布局，使用 PSScriptAnalyzer 的格式规则。命令参数、字符串和 here-string 内容保持原义。
- JavaScript 字符串内的 HTML、SQL、文章正文和浏览器测试表达式保留原内容，因此部分字符串仍为长行。格式化不是修改页面模板或业务逻辑的授权。

## 命令

```powershell
npm install
npm run format
npm run format:check

# 需要 PowerShell 7 和 PSScriptAnalyzer 模块
npm run format:powershell
npm run format:powershell:check
```

`format` 和 `format:powershell` 写入源码；带 `:check` 的命令只检查，发现不符合规则时以非零状态退出。工具版本记录在 package.json 与 package-lock.json，运行时仍只使用原有业务依赖。

PowerShell 格式脚本优先使用本轮保存在 `artifacts/source-format/tools/PSScriptAnalyzer/` 的模块，也支持系统已安装的 PSScriptAnalyzer；缺少模块会明确报错，不会执行待格式化的 PowerShell 业务脚本，也不会自动安装工具。

## 处理范围

1. 根目录业务 `.js` / `.mjs`、三份样式及 index.html。
2. scripts/、tests/ 的 JavaScript 模块，以及 thesis/generate-latex.mjs。
3. package.json、.prettierrc.json、media-sources.json。
4. database/patch_notes_mysql.sql、database/patch_missing_tables_mysql.sql、database/答辩演示_只读查询.sql。
5. 三份已有 PowerShell 脚本、格式脚本本身及其规则文件。

## 保持原样的内容

- node_modules/、缓存、上传头像、业务数据库、模型与私人备份。
- 论文源码附件和历史快照、数据库结构导出、生成的 HTML/SQL/JSON、文章原文、许可证及图片等素材。
- handwriting-data.js：自动生成的字形数据。
- study-posts.js 的 BEGIN/END SMART QUESTIONS 标记区：文章导入器生成的内容逐字保留，标记区外的业务函数正常格式化。
- database/mysql-schema.sql：mysql-schema.mjs 使用正则按固定列格式解析此文件；它已经逐列排版，保留其空格、行布局及引用格式。
- 项目书、论文正文、LaTeX 和已有代码讲解中的代码快照不批量重新排版。播放器讲解保留本次整理前的源码快照链接，避免旧行号误导阅读。

## 验证方法

本轮先保存所处理源码的副本，再检查 JavaScript 整理前后的语法树一致性（忽略位置和字面量书写形式）、生成文章块及模板字符串内容、JSON 数据和手工 SQL 的词法序列，并检查格式器重复运行不再产生变化。另根据修改范围运行现有接口和浏览器测试。

源码备份与本轮验证记录在 artifacts/source-format/。该目录只用于本地核对，不加入网站静态资源白名单。格式化不代表已经重启业务服务或执行数据库迁移。
