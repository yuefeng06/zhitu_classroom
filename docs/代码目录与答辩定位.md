# 代码目录与答辩定位

整理日期：2026-11-01。本文是当前源码导航；旧论文、PPT 中的根目录文件名可通过同目录的 `目录迁移映射.json` 找到新位置。

## 先向老师介绍整体结构

> 本项目按前后端职责组织代码。frontend 是浏览器界面，backend 是 Node.js 服务和业务接口，database 保存数据库结构与课程目录资料，scripts 是维护工具，tests 是验证代码。浏览器通过同源 /api 接口访问后台，由后台校验身份和数据归属后访问 MySQL。用户端和管理员端是业务角色，不是两套独立服务器。

```text
project/
├─ frontend/                 前端
│  ├─ index.html             HTML 页面骨架
│  ├─ js/                    原生 JavaScript 页面与交互模块

│  └─ assets/                Logo、课程封面、方向图片
├─ backend/                  Node.js 后端
│  ├─ server.mjs             HTTP 服务、API 分发、静态资源白名单
│  ├─ backend.mjs            用户业务接口
│  ├─ admin-api.mjs          后台权限及课程、章节、文章、用户、讨论维护
```

## 按一个业务说明调用顺序

以“收藏当前章节”为例：

1. 打开 `frontend/js/player.js`，搜索 `favorite`，说明点击事件如何提交 `chapterId`。
2. 打开 `backend/server.mjs`，说明 `/api` 请求进入业务接口。
3. 打开 `backend/backend.mjs`，搜索 `kind === 'favorite'`，说明会话、章节归属和写入校验。
4. 打开 `backend/database.mjs`，说明参数绑定和事务查询。
5. 打开 `database/数据库表结构说明.md` 的 favorites，说明用户与章节的联合主键。

视频上传则按 `frontend/js/admin.js → backend/admin-api.mjs → backend/video-files.mjs / backend/media.mjs → frontend/js/player.js` 讲解。视频文件不存入 MySQL；数据库章节与 JSON 片源映射各有职责。

## 运行及边界

仍从项目根目录执行 `npm start` 或 `npm run dev`；`node server.mjs` 也保留。根目录入口仅一行导入，HTTP 服务的实现位于 backend/server.mjs。

网页 URL 保持原来的 `/app.js`、`/theme.css`、`/course-images/...` 等，由服务端白名单映射到 frontend 下的文件。磁盘目录和浏览器 URL 并非一一相同；不开放任意项目目录访问。

本轮没有迁移数据库、上传文件或 .env，没有改变 API 和业务规则。现有 MySQL、data/、media-sources.json 的位置不变。历史 SQLite 文件仅用于历史资料，隔离测试显式使用临时库。

代码整理不等于重构成 Vue、React 或 Express。当前仍为原生前端与 Node.js，推荐模型是否启用要以门控与运行结果为准。
