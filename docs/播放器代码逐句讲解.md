## 先了解调用关系

`app.js` 的课程播放路由调用 `mountPlayer()`，传入页面容器、课程编号、请求函数和用户状态。该函数加载课程、创建页面、绑定交互，最后返回一个清理函数，供路由离开时调用。

本文件有两条播放路径：B 站课程使用 `iframe`，直链视频使用原生 `video`。本站的倍速按钮、弹幕、自动下一节和秒级进度保存属于原生 `video` 路径；B 站播放器内部也可能提供自身的操作，但这些操作不由本文件控制。

常见语法：`const` 定义不能重新赋值的变量绑定，绑定的对象仍能修改属性；`let` 定义可重新赋值的变量；`async` 函数返回 Promise；`await` 暂停当前异步函数、等待结果，不会阻塞整个浏览器；`=>` 是箭头函数；`?.` 在对象为 null/undefined 时停止访问；`??` 仅在左侧为 null/undefined 时使用右侧值；`||` 在左侧是假值时使用右侧值；`===` 同时比较值和类型。单独的 `}`、`)`、`;` 分别关闭作用域、调用/表达式和语句，下文结合所在语句解释。

- `api(...)`：向 `/api/courses/课程编号` 请求详情。反引号模板字符串中的 `${id}` 替换为实际课程编号。
- `await`：收到结果后再赋给 `data`。这里没有局部 `catch`，请求失败会让 `mountPlayer()` 返回的 Promise 拒绝，由调用链处理。
- `if (!isCurrent())`：若等待期间用户已经跳到别的页面，立即结束；返回空清理函数，保持返回接口一致。
- `course = data.course`、`chapters = data.chapters`：分别取出课程对象和章节数组。这两项使用一个 `const` 声明，以逗号分隔。
- `location.hash`：获得 `#/video/课程编号?chapter=章节编号&t=秒数` 一类前端路由。
- `.split('?')[1] || ''`：取问号后的查询部分，没有时使用空字符串。
- `new URLSearchParams(...)`：把查询字符串转为可通过 `get()`、`has()` 操作的对象。
- 第一个 `find()`：把 URL 中的章节编号转为数字，再查找对应章节。
- 第二个 `find()`：URL 没匹配到时，查找课程记录中的最近章节 `course.chapter_id`。
- `chapters[0]`：前两个都没找到时选择第一节；空数组则得到 `undefined`。
- `alive = true`：标记本次播放页尚未销毁。
- `cleanupMedia = () => {}`：先放一个空的媒体清理函数，实际播放器创建后再替换。
- `save = () => Promise.resolve()`：先放一个立即完成的异步保存占位函数；尚未创建直链播放器时没有进度要保存。
- `switching = false`：章节切换锁，防止同时执行多个切换过程。

## 3. 把秒数显示成时间（28—38 行）

[查看源码第 28 行](C:/Users/中堂医生/OneDrive/Desktop/project/player.js:28)

```js

  // 时间显示与本地播放偏好；不把偏好写成服务器学习记录。
  const clock = value => {
    const n = Math.max(0, Math.floor(Number(value) || 0));
    return (
      (n >= 3600 ? Math.floor(n / 3600) + ':' : '') +
      String(Math.floor(n / 60) % 60).padStart(2, '0') +
      ':' +
      String(n % 60).padStart(2, '0')
    );
  };
```

- `clock = value => {...}`：定义格式化时间的函数。
- `Number(value)`：把参数转成数值；`|| 0` 对 NaN、0 等假值使用 0。该表达式没有单独过滤 Infinity，因此不能把它说成“验证了所有非法时间”。
- `Math.floor(...)`：向下取整，去掉小数秒。
- `Math.max(0, ...)`：不显示负数。
- `n >= 3600 ? ... : ''`：满一小时才显示小时部分，小时数取 `n / 3600` 的整数。
- `Math.floor(n / 60) % 60`：计算不足一小时的分钟部分。
- `String(...).padStart(2, '0')`：转为字符串，不足两位时在左侧补 0。
- `n % 60`：计算秒的部分，同样补成两位。
- `+ ':' +`：把各部分连接起来。例如 65 秒显示 `01:05`，3665 秒显示 `1:01:05`。

## 4. 读写浏览器偏好（39—51 行）

[查看源码第 39 行](C:/Users/中堂医生/OneDrive/Desktop/project/player.js:39)

```js
  const pref = (key, fallback) => {
    try {
      return localStorage.getItem('zhitu-' + key) ?? fallback;
    } catch {
      return fallback;
    }
  };
  const setPref = (key, value) => {
    try {
      localStorage.setItem('zhitu-' + key, value);
    } catch {}
  };

```

- `pref(key, fallback)`：读取偏好，缺失或无法读取时使用默认值。
- `'zhitu-' + key`：给存储键加项目前缀，例如 `zhitu-speed`。
- `getItem(...) ?? fallback`：存储项不存在时返回 null，因而使用默认值；已存的空字符串不会被 `??` 替换。
- `try/catch`：浏览器拒绝本地存储等情况下仍允许播放器继续运行。
- `setPref(key, value)`：保存偏好。`localStorage` 保存的是字符串，布尔值也会转成 `'true'` 或 `'false'`。
- 空的 `catch {}`：忽略偏好保存失败，没有向用户报告。这些偏好仅在浏览器，不是服务器学习记录。

## 数据去向与讲解边界

| 操作 | 前端触发 | 保存位置或处理位置 |
| --- | --- | --- |
| 课程、章节、讨论加载 | 课程 GET 接口 | 后端课程查询及片源解析 |
| 最近打开章节 | POST visit | 服务端当前用户的 course_visits |
| 原生视频位置 | POST progress | chapter_playback、progress |
| 私有时间笔记 | GET/POST notes、DELETE 单条笔记 | 服务端当前用户的 notes |
| 收藏、关注、讨论、弹幕 | 对应 POST 接口 | 服务端业务表及权限校验 |
| 倍速、弹幕开关、自动下一节 | localStorage | 当前浏览器 |
| B 站播放秒数 | 本文件没有读取实现 | 由嵌入播放器管理；本站笔记手动填时间 |

`backend.mjs` 的进度接口还会校验当前会话、章节是否属于该课程、片源种类、时间范围，再在事务中更新数据。课程总进度按各章节的百分比求平均，章节等权，并非按所有视频时长加权。前端显示的 result.percent 来自该接口，不能仅凭本文件推断数据库已成功写入。

答辩可以这样概括：用户进入播放页后，系统根据链接、最近章节和第一节的优先顺序选择章节，再按片源创建对应播放器。对原生视频，页面通过媒体事件实现续播、笔记定位和进度保存，利用 Promise 队列顺序提交，并在切换章节、离开页面时清理资源。对 B 站嵌入视频，本站记录最近打开章节并提供收藏和手动时间笔记，不把访问记录当作观看完成度。
